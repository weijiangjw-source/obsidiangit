你的 `obsidian-second-brain` 已经完成初始化，下面是日常使用的操作指南。**不要被几十个命令吓到——先跑通“摄入 → 保存 → 综合”这个循环，其余的按需再查。**

### 🎯 先记住：日常只跑这四条

`/obsidian-ingest`（摄入）、`/obsidian-save`（保存对话）、`/obsidian-synthesize`（自动综合）、`/obsidian-reconcile`（调和矛盾）。这四条构成了“输入 → 沉淀 → 串联 → 纠偏”的闭环，覆盖 90% 的日常场景。

**1. `/obsidian-ingest [来源]`** — 消化外部资料
参数可以是 URL、文件路径或直接粘贴的文本。它**不会只新建一篇摘要**，而是会让知识库**围绕新知识自我重写**：实体页面（人物、项目）会被更新，概念页面如果被新来源深化或**矛盾**，也会被改写。官方数据：**每摄入一个来源，会触及 5–15 个页面**。

**2. `/obsidian-save`** — 把当前对话“存档”
扫描你与 Claude 的**整个会话**，自动识别出决策、任务、人物、想法，然后分别写入对应的正确笔记。一次 `/obsidian-save` 可以生成多篇交叉链接的笔记。适合在讨论完一个话题、做完一个决策后立刻执行。

**3. `/obsidian-synthesize`** — 让库自己“发现模式”
自动扫描全库，找出**你从未命名的模式**，并**主动写出综述页面**。你不需要事先想好“我该总结什么”。可以手动触发，也可以配置为定时 Agent 在后台运行。

**4. `/obsidian-reconcile`** — 自动解决矛盾
当新资料和旧笔记冲突时，找出矛盾并**自动调和**。与 Karpathy 原始模式“标记矛盾、等人裁决”不同，这条命令让库**自己收敛到自洽状态**。

> **建议节奏**：每周至少跑一次 `/obsidian-synthesize` + `/obsidian-reconcile`，让库保持“活体”状态；`/obsidian-ingest` 和 `/obsidian-save` 按实际输入频率执行。


### 🧠 进阶：让库“和你争论”的思考工具

这些命令不负责整理，负责**挑战你、连接你、暴露你的盲区**。

| 命令 | 作用 | 典型场景 |
| :--- | :--- | :--- |
| `/obsidian-challenge [想法/计划]` | 用你**自己的历史笔记**反驳你，找出矛盾、过去失败和错误假设 | “我想做一个 X 项目”——让库翻出你以前类似计划踩过的坑 |
| `/obsidian-connect [主题A] [主题B]` | 用库的双链图谱**桥接两个不相关的领域**，制造创造性摩擦 | “连接‘行为经济学’和‘笔记方法’”，看能碰撞出什么 |
| `/vault-deep-synthesis [主题]` | 交叉比对库中关于该主题的**所有**笔记，列出**一致点、矛盾、过时论断、空白** | 写文章或做决策前，先做一次主题层面的“体检” |
| `/obsidian-emerge` | 从**最近 30 天**的笔记中，捞出你从未命名的重复主题或模式 | 定期跑一次，发现“原来我一直在想这件事” |

**使用心法**：不要只在“想整理”的时候跑这些命令。在**做一个重要决定之前**跑 `/obsidian-challenge`，在**卡壳的时候**跑 `/obsidian-connect`，价值远高于事后整理。


### 📡 研究工具：把外部信号拉进库

| 命令 | 引擎 / 来源 | 是否需 Key | 说明 |
| :--- | :--- | :--- | :--- |
| `/research [主题]` | Perplexity（有 Key）/ 免费回退 | 可选 | 网页研究，带引用和时效标记；无 Key 时回退到 Wikipedia、arXiv、HackerNews 等 |
| `/research-deep [主题]` | Perplexity + Grok | 可选 | **先扫库找缺口，再向外补**，然后回写更新；无 Key 也可用免费回退 |
| `/x-read [URL]` | Grok | **需要** | 深读一条 X 帖子：原文 + 线程 + TL;DR + 论点 + 回复情绪 |
| `/youtube [URL]` | 内置 | 否 | 转录 + 元数据 + 高赞评论 → AI-first 摘要 |
| `/podcast [URL]` | 内置 / Whisper | 否 | Apple Podcasts 或 RSS → 转录 + 摘要 |

> 如果暂时没有配置任何 API Key，**只用 `/research` 和 `/research-deep` 的免费回退模式**就已经能跑通“外部信号 → 库”的链路，先把循环跑起来，再按需补 Key。


### 🗂️ 按需查阅：Vault 操作命令（16 条）

这些是“重型武器”，适合在需要精确操作特定实体时使用，不必日常跑：

- **`/obsidian-task`**：把一条任务加到正确的看板列，带优先级和截止日期。
- **`/obsidian-person`**：创建或更新人物笔记。
- **`/obsidian-decide`**：把决策记录到正确的项目笔记中。
- **`/obsidian-find`**：带上下文的智能搜索。
- **`/obsidian-review`**：结构化周/月复盘。
- **`/obsidian-health`**：全库审计——矛盾、缺口、过时论断、孤立笔记。
- **`/obsidian-visualize`**：生成库的 Canvas 可视化图谱。


### ⚙️ 两个与你当前配置直接相关的要点

**第一，`_CLAUDE.md` 是你的“总开关”。** 所有命令在执行前都会**先读取库根目录的 `_CLAUDE.md`**。你之前写进去的“只读区域 / 可写区域”限制，对每一条命令都生效。如果发现某条命令在你不希望它写入的文件夹里动了文件，**第一反应应该是去 `_CLAUDE.md` 里收紧规则**，而不是怀疑命令本身。

**第二，`/obsidian-save` 的“注入”是安全的。** 有用户担心 `/obsidian-save` 会把无关内容“强行注入”到重要笔记里。官方对此的说明是：**save 只归档你明确选中或当前会话中产生的洞察**，不会把整段原始对话塞进库里。如果你对某次保存的范围有疑虑，可以在执行前先告诉 Claude：“这次只保存关于 X 的部分”。
