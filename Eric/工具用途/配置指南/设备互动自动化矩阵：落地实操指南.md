# 50台设备互动自动化矩阵：落地实操指南

## 一、 硬件架构与物理环境部署

工欲善其事，必先利其器。50台设备的物理集群必须做好供电、散热和物理隔离。

- **设备选型**：统一采购 50 台同型号二手安卓手机（如红米 Note 系列，4GB+64GB 内存，系统版本保持一致，降低脚本适配成本）。
    
- **安全改造（核心）**：
    
    - **拆除原装电池**：必须拆掉所有手机电池，防止长时间高强度运行导致鼓包、发热甚至起火。
        
    - **外接供电**：使用淘宝采购的**群控主板机恒压电源板**进行外部集中供电。
        
- **物理架设**：
    
    - 使用 3-4 个**工业级 16 口带独立大功率电源的 USB Hub**。
        
    - 使用多层金属置物架配合静音散热风扇集中摆放。
        
- **网络与 IP 隔离（防连环封号）**：
    
    - **严禁共用同一个局域网 Wi-Fi**。
        
    - 为每台手机配置一张**物联网流量卡（副卡）**。通过脚本控制定时开关一次“飞行模式”来实现基站断网重连换 IP，做到“一机一卡一IP”。
        

## 二、 开源免费工具栈选型

不使用任何付费商业群控软件，全部采用开源社区成熟的稳定组件：

|模块|工具名称|开源地址 / 说明|核心作用|
|---|---|---|---|
|**底层连接**|**ADB (Android SDK)**|Google 官方开源|多机通信、批量安装、状态巡检的基石|
|**投屏与监控**|**QtScrcpy**|`barry-ran/QtScrcpy`|50屏宫格预览、分组群控、突发验证码时的人工鼠标接管|
|**自动化引擎**|**uiautomator2**|`openatx/uiautomator2`|网易开源的 Python 自动化框架，在电脑端通过多线程精准控制点击与滑动|
|**任务与语料**|**Redis + Python**|本地部署轻量级服务|存储待互动的任务队列、打乱并随机混淆评论话术库|

## 三、 抗风控与行为拟真核心策略

平台风控主要通过“机械化特征”来识别机器。脚本必须加入以下拟真对抗算法：

1. **轨迹防封（贝塞尔曲线）**：
    
    - 摒弃瞬间的线性点击或匀速直线滑动。
        
    - 在 Python 脚本中引入**三阶贝塞尔曲线算法**，让手指按下、加速、减速、弧形划过屏幕的轨迹符合物理规律。
        
2. **时间防封（高斯正态分布延迟）**：
    
    - 动作之间绝对不能采用固定时间间隔（如死板的每隔 15 秒）。
        
    - 采用随机正态分布函数（如 `time.sleep(random.uniform(a, b))`），让每个号的停留和点击时间完全随机。
        
3. **话术防封（同义词混淆库）**：
    
    - 建立多维度的同义词替换与短语随机组合矩阵，确保 50 台机器在发评论或互动时，绝不出现完全相同的文本，避开垃圾文本拦截。
        
4. **账号预热（养号期）**：
    
    - 新设备和新账号上机前，必须进行 3-5 天的拟真养号（模拟日常刷视频、随机浏览、偶尔停留），提升账号基础权重。
        

## 四、 落地实施步骤

### 阶段一：环境搭建与设备调试

1. 组装机架、改造外接电源，将 50 台手机通过 USB Hub 连接至宿主机（中高配 PC）。
    
2. 在电脑端配置 Python 环境，安装 `uiautomator2` 与 `adbutils` 库。
    
3. 验证 ADB 连接，确保 `adb devices` 能稳定识别全部 50 台设备。
    

### 阶段二：脚本编写与任务分发

1. 编写基于 Python 的自动化主控脚本，核心逻辑包含：
    
    - 启动目标 App -> 寻找指定视频 -> 模拟贝塞尔滑动 -> 触发高斯随机延迟 -> 执行点赞/关注/随机评论。
        
2. 本地启动 Redis，导入预设的视频目标池和混淆话术库。
    
3. 通过 Python 的 `asyncio` 异步协程或多线程，实现 50 台设备的异步并发调度。
    

### 阶段三：日常运维与异常处理

1. 平时通过 **QtScrcpy** 抽查多屏运行状态。
    
2. 一旦风控系统弹出滑块、验证码或人脸校验导致某台手机脚本卡死，后台会发出告警，人工直接通过 QtScrcpy 界面接管该台设备，手动完成校验后切回脚本继续自动运行。
